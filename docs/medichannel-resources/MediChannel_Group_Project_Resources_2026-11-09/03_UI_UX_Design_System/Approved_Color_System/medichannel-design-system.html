02 · Components

Reusable building blocks

Defined once as Tailwind component classes (.btn, .input, .card, .badge) so every page looks the same. In Next.js these become React components with props.

Buttons

One primary action per screen. Destructive actions always open a confirmation dialog.

Form field anatomy

Helper text sits under the field.

Phone must look like 07XXXXXXXX.

Errors appear only under the invalid field, in red, with text. Validated on the client and again on the server.

Toast & dialog

Toasts use aria-live="polite". Dialogs use the native <dialog> element, so focus is trapped and Esc closes it.

              07 · Spec coverage

              Where each rule is shown

              BR-01 Session fields, max 1–60, 5–30 min, room only for physical BR-02 Doctor and room overlap blocked BR-03 Numbers never exceed the maximum, last number handled BR-04 One active appointment per session BR-05 Booking closes 1 h (physical) or 30 min (online) before BR-06 Estimated time formula, delay recalculates BR-07 Cancel only unpaid, 3 h before, record kept BR-08 Status flow BOOKED → ARRIVED → IN_CONSULTATION → COMPLETED / NO_SHOW BR-09 Chat opens when doctor starts, read-only after BR-10 NIC, phone, email, password rules with inline errors BR-11 LKR, Asia/Colombo, history kept (status changes) RT-01 Live “now serving” RT-02 Live numbers left RT-03 Chat: typing, connection status, 1000 chars RT-04 Called, 3 away, delayed, cancelled, started Privacy Manager and Admin never see medical data Security One login error, 5 fails lock 15 minutes States Loading, error, empty, full, locked, 403, offline
