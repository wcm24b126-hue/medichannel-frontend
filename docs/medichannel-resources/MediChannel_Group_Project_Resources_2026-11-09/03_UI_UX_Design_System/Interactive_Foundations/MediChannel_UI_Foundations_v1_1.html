01 · Colour palette

Approved MediChannel blue palette, unchanged. Blue 600 is the primary action. Each role has a secondary accent for identity—not for communicating critical medical status.

Brand blue · 10 shades

Click or tap a shade to copy the HEX value.

Role accents · approved

Guest: slate; Patient: emerald; Doctor: violet; Manager: amber; Admin: rose.

Semantic colour rules

InformationSuccessWarningErrorNeutral

Use a text label with every colour; never depend on colour alone. Keep medical privacy indicators legible.

Neutral surfaces

Canvas · #F8FAFCBorder · #E2E8F0Text · #1E293B

White cards, slate headings, quiet borders, and modest shadows for a calm healthcare interface.

02 · Typography

Inter is the default Latin UI typeface, with system sans-serif fallback. For Sinhala support use an appropriate Sinhala-capable fallback; verify glyphs on actual devices.

03 · Buttons

Clear action hierarchy. Primary is for the main task, secondary for optional actions, and danger only for destructive actions. Minimum mobile target is 44px high.

Button variants

Disabled, small and loading

During a pending action, prevent duplicate submissions and show progress; enable again on completion.

04 · Inputs and form validation

Labels stay visible. Every invalid field displays its own text error underneath. This demo validates sample input locally; Spring Boot must validate it again.

08 · Alerts and notifications

In-app notifications include called, three numbers away, session delayed/cancelled and consultation started. Provide both icon and text, and ensure messages are sent only to the affected patient.

Interactive notification examples

No medical reasons, diagnosis, prescriptions or private chat content appear in notifications. The same privacy rule applies to Manager and Admin views.

10 · Responsive layout

Fluid layout with no manually chosen device profile. Mobile uses single-column forms and stackable cards. Tablets use two columns where space allows; desktops use an app sidebar and wider grids.
